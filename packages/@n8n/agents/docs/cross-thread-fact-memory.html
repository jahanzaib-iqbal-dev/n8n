Agent JSON Config
explicit opt-in

memory.crossThreadFacts enables extraction and recall.

Default is off. Existing memory.enabled does not silently enable cross-thread facts. n8n JSON config stores an embedding model id and credential reference.
semanticRecall excluded

Stale POC surface remains untouched and unused here.

semanticRecall is not a dependency, fallback, or configuration shortcut for this feature.
user identity

resourceId maps to the user id.

The SDK contract uses resourceId as the user scope. No extra userId field is introduced.
SDK Memory Builder
new memory surface

Memory.crossThreadFacts(...) produces SDK config.

Separate from working memory and separate from semantic recall. SDK consumers provide the embedding model and may override prompt templates.
backend capability

Configured memory must implement fact storage and search.

The feature extends the configured backend. It does not create a second database.
Agent Runtime
persist turn

Messages are saved before extraction is scheduled.

Only successful terminal turns enter the fact extraction path. Default runtime behavior tracks extraction as background work.
background task

Extraction does not block run completion by default.

sync: true keeps the old awaited behavior for smoke tests, evals, and deterministic local checks.
require agentId

Runtime passes agentId + resourceId to memory calls.

n8n injects the agent entity id. resourceId remains the user id.
register recall_memory

Built-in tool appears only when feature is enabled.

The tool is not auto prompt injection. The model must call it explicitly.
Fact Extractor
atomic facts

Extractor reads latest user/assistant pair and emits short facts.

Fact text is capped by config, defaulting to 240 characters in the SDK foundation.
hash and embed

Trimmed content is hashed, deduped, then embedded.

Exact hash dedupe only. Embedding calls use the SDK consumer supplied Vercel AI embedding model.
non-blocking failures

Extractor, JSON, and embedding errors emit warnings and continue.

The visible agent response and run completion are not failed by background fact memory errors.
N8nMemory / App DB
agents_memory_facts

Durable facts live in the existing app database.

No sidecar SQLite file. No SDK-local persistent backend is reintroduced.
unique scope hash

agentId, resourceId, contentHash prevents duplicates.

The same user can have separate fact sets for separate agents.
portable retrieval

Lexical and vector scores are computed in application code.

No vec0, FTS5, pgvector, or DB-specific full-text dependency in v1.
recall_memory Tool
query

The model calls recall_memory(query) explicitly.

No automatic injection into the system prompt or message list.
ranked facts

RRF combines lexical and vector candidates, then recency weights.

Either lexical or vector signals can introduce a candidate.
model output

Model sees fact content and creation time.

Raw debug output may keep score breakdowns for tests and tuning.

Paths

runtime contract

Write Path

  1. Turn finishes and messages persist through configured memory.
  2. Runtime schedules extraction with agentId + resourceId.
  3. Default mode tracks extraction in the background; sync: true awaits it for smoke tests and evals.
  4. Extractor returns zero or more short atomic facts.
  5. Content hash skips exact duplicates inside the user and agent scope.
  6. New facts are embedded through the configured model and stored in agents_memory_facts.

Read Path

  1. Model decides to call recall_memory(query).
  2. Tool searches only the active agentId + resourceId scope.
  3. Lexical and vector candidate sets are ranked independently.
  4. RRF fuses candidates and recency weighting adjusts final order.
  5. Top facts return to the model without injecting hidden prompt context.

Failure Path

  1. Extraction call fails, emits malformed JSON, or embedding fails.
  2. Runtime emits a background memory error event with context.
  3. No retry, no queue, no blocked run completion, no user-facing run failure in v1.

Scope Boundary

  1. agentId separates facts across agents.
  2. resourceId is the user id.
  3. Storage and recall both require the same pair.

Identity

resourceId is the user id. The fact scope is exactly agentId + resourceId.

No Sidecar DB

The feature extends the configured N8nMemory app-DB backend.

No Auto Injection

Facts are recalled through the tool only. They are not pushed into prompts by default.

Non-Blocking

Extractor model calls, embeddings, storage, and memory errors run after completion unless sync: true is set.
